# System Architecture: Financial PDF Chat

## Overview
This system is a **Retrieval-Augmented Generation (RAG)** engine designed specifically for complex financial documents. It prioritizes **accuracy** and **evidence-based answers** over speed, ensuring that every piece of information generated by the AI is traceable to a specific page in the source PDF.

## Core Components

### 1. Ingestion Layer (The "Eyes")
*   **Component**: `PDFIngestor` (`backend/ingest.py`)
*   **Technology**: **Docling** (IBM Research) + **HybridChunker**
*   **Why**: Standard PDF parsers (like PyPDF) extract text as a "soup" of characters, destroying tables and layout.
*   **How it works**:
    1.  **Parse**: Docling analyzes the visual layout to identify headers, reading order, and table boundaries.
    2.  **Hybrid Chunking**: Instead of arbitrarily splitting text every 500 characters, we chunk **semantically** (e.g., "whole paragraph", "whole list item", "whole table row").
    3.  **Metadata**: Every chunk is tagged with its origin Page Number, which is preserved throughout the pipeline for citations.

### 2. Semantic Storage (The "Memory")
*   **Component**: `RAGSystem` (`backend/rag.py`)
*   **Technology**: **FAISS** (Facebook AI Similarity Search) + **SentenceTransformers** (`all-MiniLM-L6-v2`)
*   **Why**: We need to find the "needle in the haystack" (the specific revenue figure in a 100-page report).
*   **How it works**:
    1.  Text chunks are converted into 384-dimensional vectors (numerical representations of meaning).
    2.  These vectors are stored in an **In-Memory FAISS Index** for < 1ms retrieval speeds.
    3.  We use an ephemeral index (created per session) to ensure data isolation between different users.

### 3. Reasoning Engine (The "Brain")
*   **Component**: `GeminiClient` (`backend/llm.py`)
*   **Technology**: **Google Gemini 1.5 Flash**
*   **Why**: "Flash" models offer the best balance of low latency, huge context windows, and low cost for high-volume text analysis.
*   **How it works**:
    1.  The system retrieves the Top-5 most relevant text chunks from FAISS based on the user's question.
    2.  A **Strict System Prompt** forces the LLM to answer *only* using those chunks.
    3.  The LLM is required to insert `[Source X]` citations for every claim.

### 4. User Interface (The "Face")
*   **Technology**: **Streamlit**
*   **Key Feature**: **"Evidence Panel"**:
    *   Unlike black-box AI, our UI maps the `[Source X]` citation back to the **actual raw text** from the PDF.
    *   This allows the user to audit the AI—instantly verifying if the data is real or a hallucination.
